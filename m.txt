Set the session cookie with plain HTML, and serve with run_as_web_server

rio.Image treats its argument as an asset path and rejected the
/rio/cookies/... URL with "Cannot create asset from input", which crashed the
session refresh right after a successful demo login.

- Render the cookie URL as a hidden 1px <img> via rio.Html instead, so the
  browser fetches it as a subresource and applies Set-Cookie without navigating.
- Use run_as_web_server in run_app.py and main.py. run_in_browser also tries to
  open a browser, which is wrong on a headless host.

Verified end to end: demo login lands on the dashboard, the login survives a
reload, and /dashboard, /cycles, /excel, /alerts and /chart/RELIANCE all return
200 and stay on their URL when signed in. 48 tests pass.
